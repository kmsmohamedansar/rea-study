# Rules for working on the REA study

Same rules as the owner's decision-models project. Follow them for every change.

1. **Plan limits.** No paid API or service. Ghidra only (free). No Hopper, no IDA. Claude Pro is the owner's existing subscription.
2. **Targets.** Only programs we hold the answer to: written for this study, open source with public source, or practice binaries with published solutions. No live commercial sites or apps. No retail, grocery or CPG. Nothing from the owner's employer.
3. **Fairness.** One model, one effort setting, one prompt, one machine for every arm. Only the tool changes. Answer keys and marking rules are frozen before the first scored run. Held-out targets are scored once, at the end.
4. **Honesty about REA and Lean REA.** We test what they do in public. Never claim to know how they work inside.
5. **Language.** Plain words. No em dashes. Explain any jargon once.
6. **Evidence.** Keep NOTES.md dated. Run code and show real output before claiming it works. Record failures honestly.
7. **Numbers.** Only numbers from runs in this repo, with the machine named. Licence of every tool checked and recorded before use.
8. **Publishing.** Don't change the portfolio site until the owner says so.
9. **Finish.** Report in the shape of decision-models/paper/report.md, claims ledger, results.
